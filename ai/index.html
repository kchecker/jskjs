The advantages

Why ask your agent to use jsKjs?

01

One mental model, not four

An agent asked to add "live search with a fade-in" to a jQuery + htmx + Alpine + GSAP page must juggle four APIs, load orders and overlapping ideas of state. With jsKjs there is one $, one attribute prefix and one rules file.

02

A closed, written-down API

The rules file lists every available method and every common method that is not available. Agents hallucinate less when the boundary is explicit — and when they want something missing, the rules tell them to say so instead of faking it.

03

Changes you can review at a glance

<form kj-post="/subscribe.php" kj-target="#msg"> says what it does. Declarative diffs are short, local to the HTML they affect, and easy to approve — the opposite of a 40-line handler buried in a script file.

04

Training data that already transfers

Models have read an enormous amount of jQuery. jsKjs keeps those names and signatures, so the agent's instincts are mostly right from the first prompt; the rules file covers the differences.

05

No build step to break

Agents fail most often in toolchains: bundler configs, version conflicts, missing dev servers. A jsKjs page is a file you open in a browser. The agent can verify its own work, and it deploys to any PHP shared host — like the one this site runs on.

06

Small enough to read in full

The whole readable library is about 40 KB of source — a few thousand tokens. When an agent is unsure how something behaves, it can read the actual implementation instead of guessing.

07

Server-rendered HTML plays to agent strengths

Hyper endpoints return HTML fragments. Agents write small PHP, Python or Node handlers well, and escaping output there is one obvious line.

08

Fast pages by default

About 8.1 KB instead of ~90 KB for the four libraries it replaces, with zero dependencies. Performance is part of what you ship, even when an AI wrote it.

Honest limitsjsKjs is for server-rendered sites, dashboards, marketing pages, forms and interactive widgets. A large single-page app with client-side routing and hundreds of components is still a job for a framework. Pulse needs 'unsafe-eval' under a strict CSP. And it is a young library — the rules file lists what is not included so your agent can tell you instead of improvising.

How to ask

Three steps

  1. 1

    Drop in the rules

    Copy one file for your tool — or AGENTS.md, which most agents read. Get the kit.

  2. 2

    Say one sentence

    Start your request with “Use jsKjs”. The rules do the rest: one script tag, attributes first, real APIs only.

  3. 3

    Review the HTML

    kj-post="/save.php" kj-target="#msg" reads like a sentence. Approve, open the file, done.

The one sentence

Prompt
Build this page with jsKjs (https://jskjs.org). Load only https://jskjs.org/cdn/1.0.0/jskjs.min.js — no jQuery, htmx, Alpine.js or GSAP. Prefer kj-* attributes for server requests and kj-data for UI state; use $() only when attributes can't express it. Read https://jskjs.org/llms-full.txt first if you can.
