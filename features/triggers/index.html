Hyper · htmx-style

Triggers & debouncing

Fire on any event, and debounce it in the attribute: kj-trigger="keyup delay:400ms" turns an input into live, server-validated UI.

Without kj-trigger, elements use the natural event: submit for forms, change for inputs and selects, click for everything else. Name any DOM event to override it, and add delay:Nms to wait until the user pauses — one request per pause instead of one per keystroke.

Three special triggers handle timing rather than events: load (immediately), revealed (when scrolled into view) and every Ns (polling). They have their own pages: lazy loading and polling.

    Trigger cheatsheet

    HTML
    <input name="q" kj-get="/search" kj-trigger="keyup delay:300ms" kj-target="#hits">
<div kj-get="/preview" kj-trigger="mouseenter" kj-target="#card">Hover</div>
<form kj-post="/save" kj-trigger="change">…autosave on any field change…</form>
<div kj-get="/widgets/weather" kj-trigger="load"></div>
<div kj-get="/comments" kj-trigger="revealed"></div>
<span kj-get="/price" kj-trigger="every 5s"></span>

    API

    kj-trigger="event [delay:Nms] | load | revealed | every Ns"

    When to fire: any DOM event (with optional debounce), load (immediately), revealed (when scrolled into view, via IntersectionObserver), or every Ns (polling).

    Reference: kj-trigger →

    Migrating

    Coming from htmxSupported: an event name, delay:, load, revealed, every Ns. Not included: multiple events in one trigger, changed, once, throttle:, from:, intersect options and [filter] expressions.
