Hyper · htmx-style

Polling

Live-ish data with one attribute: kj-trigger="every 2s". Remove the element and polling stops by itself.

Polling is the simplest real-time technique there is, and for dashboards, build status and prices it is often all you need. Each tick is an ordinary request, so caching, auth and error handling work as usual.

jsKjs stops polling when the element is removed from the document, so swapping a panel out never leaves a timer running in the background. To pause, remove the element; to resume, insert fresh markup — it is wired automatically.

  <div class="poll-card">
    <p class="label" style="margin:0 0 10px">KJS / USD · every 2s</p>
    <div id="tick-slot"><div id="ticker" kj-get="/api/ticker.php" kj-trigger="every 2s">Waiting for the first tick…</div></div>

  </div>
  <div class="poll-card">
    <p class="label" style="margin:0 0 10px">Server clock · every 1s</p>
    <div kj-get="/api/time.php" kj-trigger="every 1s">…</div>
  </div>
</div>
<div class="row" style="margin-top:12px"><button type="button" id="tick-pause" aria-pressed="false">Pause ticker</button></div>
JavaScript
let polls = 0;
// Delegated: keeps working after the ticker element is replaced
$(document).on('kj:after', '#ticker', () => $('#tick-meta').text('kj:after fired ' + (++polls) + ' times'));

$('#tick-pause').on('click', function () {
  const pause = $(this).attr('aria-pressed') !== 'true';
  if (pause) $('#ticker').remove();     // removed → its polling stops by itself
  else $('#tick-slot').html('<div id="ticker" kj-get="/api/ticker.php" kj-trigger="every 2s">Resuming…</div>');  // auto-wired
  $(this).attr('aria-pressed', String(pause)).text(pause ? 'Resume ticker' : 'Pause ticker');
});

API

kj-trigger="event [delay:Nms] | load | revealed | every Ns"

When to fire: any DOM event (with optional debounce), load (immediately), revealed (when scrolled into view, via IntersectionObserver), or every Ns (polling).

Reference: kj-trigger →
kj:before · kj:after · kj:error · kj:load

kj:before (before the request), kj:after (response received, before the swap; detail.html) and kj:error (detail.error.status) fire on the requesting element. kj:load fires on the target after the swap — or on its former parent when outerHTML replaced it. All bubble.

Triggers & debouncing
