Hyper · htmx-style

Lazy loading & infinite scroll

kj-trigger="revealed" waits until an element scrolls into view. Make the last item of each page load the next one and you have infinite scroll — in HTML.

How the infinite feed works

Each page the server returns ends with a sentinel: a list item carrying kj-get="/api/page.php?p=N+1", kj-trigger="revealed" and kj-swap="outerHTML". When it scrolls into view, it replaces itself with the next page — which ends with the next sentinel. The last page simply doesn't include one.

revealed uses an IntersectionObserver, fires once, and works inside scrollable containers. Use kj-trigger="load" for content that should arrive right after the page renders, such as a slow widget you don't want to block the page on.

API

kj-trigger="event [delay:Nms] | load | revealed | every Ns"

When to fire: any DOM event (with optional debounce), load (immediately), revealed (when scrolled into view, via IntersectionObserver), or every Ns (polling).

Reference: kj-trigger →
kj-swap="innerHTML | outerHTML | textContent | beforebegin | afterbegin | beforeend | afterend | none"

How the response is inserted into the target. outerHTML replaces the target entirely; the four position values insert adjacent to it; none makes the request without touching the DOM.
