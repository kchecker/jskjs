Attributes, properties & data

Three different things, three methods: .attr() for HTML attributes, .prop() for live DOM properties, .data() for values you attach to elements.

Which one do I use?

  • .attr() reads and writes what is in the HTML: href, aria-*, role. Screen readers and CSS selectors see these.
  • .prop() touches the live DOM object: checked, disabled, value, scrollHeight. Use it for state that changes after load.
  • .data() reads data-* attributes (JSON is parsed for you) and stores anything — objects, dates, functions — against an element.

Leak-free by construction

Stored data lives in a WeakMap keyed by the element. When the element is gone, so is its data. Nothing is written onto your nodes, and there is no global cache to clean up.

JavaScript
const $card = $('#user-card');

function inspect(note) {
  $('#attr-out').text(note + '\n\n' +
    ".data('user')         → " + JSON.stringify($card.data('user')) + '\n' +
    ".attr('data-user')    → " + $card.attr('data-user') + '\n' +
    ".prop('disabled')     → " + $('#plan-fields').prop('disabled') + '\n' +
    ".attr('aria-pressed') → " + $('#fav').attr('aria-pressed'));
}

$('#read').on('click', () => inspect('data-* JSON is parsed into an object for you.'));

$('#upgrade').on('click', () => {
  const user = $card.data('user');
  $card.data('user', { ...user, plan: 'team', seats: user.seats + 5 });   // stored in a WeakMap
  $card.find('.plan').text('team · ' + $card.data('user').seats + ' seats');
  inspect('.data() stored a new object — the HTML attribute is untouched.');
});

$('#lock').on('click', function () {
  const locked = !$('#plan-fields').prop('disabled');
  $('#plan-fields').prop('disabled', locked);          // live DOM property
  $(this).text(locked ? 'Unlock fields' : 'Lock fields');
  inspect('.prop() flipped the live disabled property.');
});

$('#fav').on('click', function () {
  const on = $(this).attr('aria-pressed') !== 'true';
  $(this).attr('aria-pressed', String(on)).text(on ? '★ Favourite' : '☆ Favourite');
  inspect('.attr() wrote aria-pressed — screen readers announce the new state.');
});

inspect('Ready. Try the buttons.');

API
.attr(name [, value]) · .attr(object) → string | self
Get an attribute from the first element, or set one or many on all elements.

.removeAttr(name) → self

.prop(name [, value]) → any | self
Get or set a DOM property (as opposed to an HTML attribute) — checked, disabled, selectedIndex, etc.
Reference: .prop() →
.data([key [, value]]) · .data(object) → any | self
Read data-* attributes (JSON auto-parsed) or store arbitrary values against elements. Stored values live in a WeakMap — no memory leaks, no cleanup.
Reference: .data() →
.removeData(key) → self
Delete a stored data value.
Reference: .removeData() →
.val([value]) → any | self
Get or set form values. Checkboxes read/write booleans; multi-selects read as arrays.

Migrating
Coming from jQuery.data() behaves the same (JSON parsing, object stores). One deliberate difference: .val() on a checkbox returns true/false rather than its value attribute — use .attr("value") if you need that.
